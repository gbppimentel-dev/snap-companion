# v0.5.35 — live maps and the updated Snap companion

This release publishes the APK work since the first public v0.5.24 release. It
updates the original app in place: same package, baseline signer and private data.
A separate Next app or Eden Duo mod is not needed. The v0.5.24 release is preserved.

## New since v0.5.24

- Bundled Thor-specific read-only game reader for supported current course,
  variant, selected research level, rail position and render-camera fields.
- Thirty expandable illustrated maps, 143 terrain/route assets and 1,403 authored
  sightings. NEO-ONE trail, named sections, current-path course progress and known
  split/rejoin accounting; guarded camera/lens cone where aligned.
- Default Follow, retained zoom, sharper fixed-size pins and separate Pokémon,
  Missing Diamonds, LenTalk and Hidden modes. Map gestures do not control the game.
- Snap-asset header, navigation and native controller/stick artwork; compact
  Photodex grids, shared course filters, photo-book readers and four-photo albums.
- Illustrated LenTalk cards, completion status, full solutions and optional
  reviewed detailed notes for 13 requests. Guide groups courses by island/time
  and shows encounter category coverage.
- Star-photo methods with course/setup/tool/timing details: 58 reviewed methods
  plus 442 existing scoped instructions cover 499 categories. Other categories
  retain general hints. 258 existing multi-hint groups display 612 separate
  options with Option/OR sections.
- Prioritized newest saved snapshots and improvements to fallback artwork,
  image presentation and reference readers.
- Normal Live dashboard during Photo Selection; automatic selection comparison
  and grading helper pages are removed.
- Event/handoff recovery retains fresh scoped event positions, keeps branch
  history through short gaps and briefly labels a stationary last position
  while reconnecting. It never invents movement from a timer.
- Quiet header battery icon and current charge percentage only. No Good/health
  label, capacity estimate, additional service or network access.

## Install/update

Install `SnapCompanion-v0.5.35.apk` over the existing companion. Do not uninstall
or clear data. Pair the Snap shortcut in Cocoon with Snap Companion on the bottom
screen. Connections start automatically on the supported setup; respond to Android
permission prompts if presented. See [setup](../SETUP.md).

## Target and limitations

Checked target: AYN Thor / Android 13, compatible AYN firmware service, original
Eden package `dev.eden.eden_emulator` (observed 0.2.1), exact New Pokémon Snap 2.0.1
layout. Other environments are unverified. English OCR is still used for supported
screen-only observations; not all fields have a memory provider.

Map calibration covers portions of 30 illustrations / 121 of 123 known rails.
Two rails, rejected intervals and some seasonal/branch variants remain unplaced
or unverified. Pins are authored sightings, not live actors or current pose
availability. Forest/Camp whole-course totals remain neutral where continuation
data is incomplete. No live target/pose recognition or ungraded-photo ranking.
Photo images can arrive after metadata; already black source images cannot be
reconstructed. All-course, new-save, restart, long-session and thermal acceptance
remain incomplete; no sustained 60 FPS guarantee is made.

## Validation

Required local release checks cover the Android unit/Robolectric suite, JS
model/map suite, offline diagnostics, native reader checks, lint, publication
boundary and original package/signer. Browser checks cover the main UI, maps,
filters, readers, option grouping and battery-only header at multiple sizes.
Versioned validation metadata records the exact counts and scope.

The preceding code62 APK was installed in place on Thor; available charge/Good
health rendering was observed, then the requested Good label was removed for this
release. Event/fork recovery has source/model/browser checks, but the latest fix
has **no completed live split-path run**. This release does not upgrade local
checks into all-course hardware acceptance. Final code63 deployment observations
are recorded in the release validation metadata.

Published documentation screenshots use invented progress and simulated readings,
with no personal saves/photos or claimed performance measurements.
